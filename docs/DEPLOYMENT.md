The release artifact is the `dist/` directory generated by `npm run build`. It contains the static pages, self-hosted fonts, public résumé, screenshots, and an explicitly packaged Relay Desk source archive. It does not run the Relay Desk server.

## Cloudflare Pages

The implementation follows the [Astro static output guide](https://docs.astro.build/en/guides/deploy/) and [Cloudflare’s Astro deployment guide](https://developers.cloudflare.com/pages/framework-guides/deploy-an-astro-site/), reviewed on 11 November 2026. Check the current Pages plan limits before deploying; no plan, account, or domain has been purchased by this implementation.

1. Choose a Pages project in Harold’s hosting account. Connect the standalone [portfolio repository](https://github.com/ngyathin16/harold-ng-portfolio) for Git integration. The source repository is public. Alternatively, upload a locally built `dist/` using Pages Direct Upload.
2. Configure Node.js 24 (`NODE_VERSION=24`), build command `npm run build`, and output directory `dist`. The repository root is the build root. No adapter or server runtime is needed.
3. Set `SITE_URL` to the final HTTPS origin, without a path. Use the actual assigned Pages hostname until a domain is purchased and connected. This value controls canonical and social URLs, sitemap entries, and indexability.
4. Build and verify the production artifact. For a local PowerShell release build, set `$env:SITE_URL = 'https://YOUR-ACTUAL-HOSTNAME'`, then run `npm run build`. Replace the example with the real hostname; do not deploy a placeholder.
5. Upload only `dist/`. Do not upload the repository root, `.worktrees`, `artifacts`, or any project `.env` or database.
6. Verify `/`, `/work/ifc-gpt/`, `/work/relay-desk/`, `/resume.pdf`, `/robots.txt`, `/sitemap.xml`, `/images/social-preview.png`, and a nonexistent URL returning the custom 404 with HTTP status 404. Follow the contact links, open the PDF and source archive, and repeat mobile/keyboard checks.

## Domain

The preference is `harold.work`, followed by `haroldng.dev` and `haroldng.work`. Check availability, registration price, and annual renewal price at purchase time. No domain ownership or final selection is established by this repository.

Once a domain is selected and purchased, add it through the Pages project’s custom-domain flow, follow the DNS instructions for that account, and wait for HTTPS activation. Update `SITE_URL`, rebuild, and verify canonical/sitemap/social URLs and redirects before sharing the public URL. No local build can prove public DNS or TLS readiness.

## Preview builds

Build without `SITE_URL` to keep a local preview unindexed. Pages branch previews should also omit `SITE_URL` if they should be unindexed; check their generated robots and metadata. A `noindex` tag is an indexing instruction, not an access control.

## Maintenance

- Update case studies in `content/work/`; run `npm run build` to validate metadata.
- Regenerate the Relay Desk archive after app changes with `python scripts/package-relay.py --source ../relay-desk`, pointing to the standalone application checkout.
- Regenerate the résumé from its Markdown source and check the PDF visually and by text extraction.
- Re-run browser and Lighthouse checks after changes affecting content, layout, or assets. See [verification](VERIFICATION.md) for actual recorded conditions and results.
- Keep the Node/SQLite demo local until a separate hosting, access, and retention decision is made.
