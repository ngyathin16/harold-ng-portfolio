The 120-second exhaustive solver target is unchanged. The 300-second Job deadline includes startup/compilation/persistence/shutdown and does not establish an SL-05 pass. The operator memory/staging limits are initial admission settings; a backup larger than these must fail before staging, then be resized only with reviewed memory and cost evidence.

Nominal database connections: API `2×4=8`, dispatch `2×2=4`, searches `2×2=4`, operator reserve 8, administration reserve 8 = **32**. Qualify this against the actual provider endpoint and pooler. Enforce runtime PostgreSQL role connection limits and test exhaustion; Cloud Run scale/rollout behavior alone is not a connection hard cap. Reserve capacity for dump/snapshot connections and concurrent operator lock contenders. Direct sessions are required for operators, migration locks and dispatcher reconciliation. URLs must specify `sslmode=verify-full` and a trusted root certificate (`sslrootcert=system` where supported by the packaged client, otherwise mount the provider root).

The API runs Uvicorn with forwarding-header trust disabled. Serverless mode currently maps requests to one shared network quota bucket; forged forwarding headers, host aliases and replica changes cannot give an attacker a new bucket. This conservatively groups unrelated visitors. A trustworthy per-visitor ingress identity and its load behavior remain an explicit hosted qualification item before public launch. Do not enable `--forwarded-allow-ips=*` as a shortcut.

`/live` checks only the process and is used by platform startup/liveness probes. `/ready` and `/health` inspect database readiness without public quota writes; these reads can wake the database. Queue availability is separate from process liveness. Empty worker queues do not require permanent worker processes. GET/HEAD research export routes remain retired.

## Operators, pause and recovery

Commands are `python -m ops.serverless backup|verify|prune|cleanup|import|restore`. Each runs once. Database URL comes from `RESEARCH_OPERATOR_DATABASE_URL`; `RESEARCH_OPERATOR_ENDPOINT_MODE=direct` prevents accidental transaction-pooler use. R2 objects and completed backup sets use distinct `RESEARCH_OBJECT_PREFIX`/`RESEARCH_BACKUP_PREFIX`; `RESEARCH_REPORT_PREFIX` identifies durable sanitized reports. Sources are authoritative in R2, not container mounts. Imports need `RESEARCH_IMPORT_BUNDLE_KEY`, `RESEARCH_IMPORT_RESTORED_BYTES` and `RESEARCH_IMPORT_VERIFY_BYTES` for the immutable remote prefix, decompression reservation and logical-hash scratch reservation. Restore additionally needs an isolated `*_restore_test` endpoint, `RESEARCH_RESTORE_BASELINE_JSON`, `RESEARCH_BACKUP_ID` and distinct `RESEARCH_RESTORE_OBJECT_PREFIX`. Its identity also receives the source backup-reader secret as `RESEARCH_BACKUP_DATABASE_URL`, so retention is locked during retrieval. API, worker and Scheduler identities cannot invoke restore. Exact secret references and execution override shapes are in the [module README](../projects/research-workspace/deploy/serverless/README.md).

Proposed schedules are backup daily at 03:00, prune at 05:00, cleanup at 06:00 Hong Kong time; retries are zero at Scheduler and Job level. Verify runs explicitly or as part of backup/prune verification. Shared session advisory locking excludes conflicting operations across containers and releases on lost sessions. Credentials, memory limits and kill/restart behavior still need real provider testing. Retention remains seven daily/four weekly and at least one verified set, RPO 24 hours, RTO two hours measured through isolated browser/API/worker availability.

To stop new searches and dispatch, use `python -m ops.serverless_control pause` through an independently authenticated operator connection. Preserve accepted outbox rows, source publications and results. Set `enable_reconciliation=false` and `enable_operator_schedules=false` in the environment's private tfvars and apply the reviewed change. Cloud Tasks may still deliver wakeups; the database switch remains authoritative. Do not delete the queue.

The API and dispatcher require `RESEARCH_DISPATCH_MARKER_BUCKET` and use `RESEARCH_DISPATCH_MARKER_PREFIX=dispatch/` inside separate environment buckets. Do not add lifecycle expiry or manually remove active hints. For initial rollout and after restore, keep dispatch paused and run `python -m ops.serverless_control repair-markers`. The repair recreates hints for active generations and outstanding executions. Resume with `python -m ops.serverless_control resume` after capacity, database and execution outcomes are known; this repairs hints again before clearing the switch in the same transaction. Failed repair leaves dispatch paused. Enable reconciliation, observe queued progress, then resume operator schedules independently.

The independent operator needs create permission on the environment's hint bucket as well as the direct verified database connection. A Cloud Run operator uses its attached identity. A local operator sets `RESEARCH_OPERATOR_GOOGLE_ACCESS_TOKEN` to a short-lived token obtained from its already authenticated Google CLI, without printing it or storing it in Git. The command closes its HTTP client and sanitizes failures. Do not use a service-account key or runtime database owner credentials for this workflow.

An uncertain launch retains its reservation until the cloud execution is found and terminal. A reservation expiry alone never authorizes replacement. If no execution can be located after a lost launch acknowledgement, automated recovery may remain blocked; preserve the reservation and escalate with query/generation/reservation IDs, operation ID and exhaustive allowlisted Job execution inventory. The current implementation must not be credited with the hosted 15-minute bound for this case without evidence.

## Alerts and response

Terraform configures platform failed-Job alerts, dispatcher log alerts for queue age over 60 seconds, uncertain launches and expired leases, and project budget thresholds 50/90/100%. Runtime logs correlate work IDs without session tokens. Recipients are supplied as verified channel resource names. Notification **delivery has not been tested**.

| Signal | Initial response and release requirement |
| --- | --- |
| Queue age / dispatch failure / uncertain execution | Check dependencies, admission and actual cloud execution before any retry; preserve the accepted query. Record capacity wait separately. |
| Expired lease / failed Job | Check fenced owner, application attempt count and terminal cloud outcome. Deterministic solver failures must not incur repeated enumeration. |
| Capacity stale or insufficient | Pause allocations; refresh trusted provider measurements and investigate growth. Never automatically raise limits. Provider collector and capacity alert binding remain pending. |
| Backup age approaching 24h / restore failure | Preserve last usable set, inspect durable report and run an isolated verification. Backup-age alert binding remains pending; failed restore Jobs share the platform failure alert. |
| Cost threshold | Pause admission and schedules if needed. Alerts do not enforce a cap; review provider/network usage independently. |
